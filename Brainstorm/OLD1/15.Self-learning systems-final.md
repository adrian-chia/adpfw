# 15. Self-Learning Systems

## 1. Overview
In the context of Open Banking, **self-learning systems** utilize advanced machine learning algorithms—specifically Temporal Heterogeneous Graph Neural Networks (GNNs) and streaming analytics—to dynamically establish baselines of normal API behavior. Rather than relying solely on static firewalls, Web Application Firewalls (WAFs), or rate-limit rules, these systems continuously ingest real-time transaction telemetry. 

By modeling interactions (e.g., users, devices, OAuth tokens, consents, and API endpoints) as dynamic graphs, self-learning systems can detect complex threats such as:
- Broken Object Level Authorization (BOLA) and object-ID enumeration.
- Credential stuffing and stolen-token misuse.
- Low-and-slow data exfiltration that stays under static rate limits.
- Compromised third-party provider (TPP) anomalous behavior.

## 2. Thesis Statements

**Thesis Statement 1: Detection Superiority**
> A temporal heterogeneous graph-learning system that integrates Open Banking API telemetry with identities, OAuth tokens, consents, scopes, and account-access relationships can detect distributed data exfiltration and BOLA-style attacks more effectively than static rule-based firewalls and standard request-local anomaly detection baselines.

**Thesis Statement 2: Real-Time Efficacy**
> Streaming temporal graph anomaly detection pipelines enable financial institutions to execute real-time decision-making on API traffic, effectively mitigating low-and-slow authorization abuse with minimal time-to-detection and without degrading user experience latency.

**Thesis Statement 3: Hybrid & Context-Aware Architecture**
> A hybrid self-learning architecture combining deterministic API-security rules with authorization-aware graph-based anomaly scoring (evaluating consent, token lineage, and OAuth scope) produces higher precision and lower false-positive rates for Open Banking API abuse than either approach alone.

## 3. Literature Review

The shift toward Open Banking has driven a massive increase in API traffic, necessitating dynamic, self-adapting systems. Traditional tabular anomaly detection or batch-driven architectures often fail to capture the complex, relational nature of API abuse. 

### Graph Neural Networks (GNNs) for Financial Anomaly Detection
GNNs have emerged as a superior approach for identifying complex patterns in financial networks because they model relationships (edges) between entities (nodes) rather than treating each transaction in isolation. Systematic reviews indicate that GNNs significantly outperform traditional machine learning methods in identifying sophisticated, distributed fraud patterns.
* **Supports Thesis 1 (Detection Superiority):** Establishes that GNNs outperform traditional models in detecting complex, relational fraud patterns.
* **Relevant Literature:** *Detecting Financial Fraud in Real-Time Transactions Using Graph Neural Networks and Anomaly Detection Techniques* (Zakaria et al., 2025) synthesizes graph-based methodologies and demonstrates how modeling multi-relational ecosystems (accounts, devices, merchants) via GNNs captures complex, coordinated fraud patterns that isolated transaction analyses miss.

### Temporal Graph Learning and API Security
Open Banking requests are not static; a token may behave normally at issuance but turn malicious hours later. Temporal graph learning (TGL) captures both the spatial dependencies (relationships) and temporal dynamics (how relationships evolve). Modeling Open Banking API logs as continuous-time execution graphs allows for the detection of abnormal access edges—such as a Third-Party Provider (TPP) gradually broadening the set of accounts it queries.
* **Supports Thesis 3 (Hybrid & Context-Aware Architecture):** Emphasizes the necessity of modeling both spatial dependencies and temporal dynamics to evaluate context and changing relationships over time.
* **Relevant Literature:** *Graph Neural Networks for Financial Fraud Detection: A Review* (Cheng et al., 2024) addresses methodological gaps in managing temporal dynamics and real-world deployment challenges.

* **Relevant Literature:** *Hybrid AI Models Combining Rules and Machine Learning for Financial Fraud Control in the United States* (Rabbi et al., 2026) examines how combining deterministic rules with machine learning significantly reduces false positives (by 58%) while maintaining adaptability against novel and emerging threats.

### Overcoming Real-Time and Production Constraints
A major challenge for deploying GNNs in cybersecurity is the latency introduced by graph-neighbor queries during model inference. High latency degrades the user experience for legitimate API consumers. Architectures like the BRIGHT framework address this by decoupling heavy batch-embedding calculations from real-time transaction scoring, achieving massive reductions in latency (e.g., P99 latency reduced by over 75%) while maintaining high detection precision.
* **Supports Thesis 2 (Real-Time Efficacy):** Proves that specific architectural choices can solve latency issues, enabling real-time anomaly detection without degrading API performance.
* **Relevant Literature:** *BRIGHT — Graph Neural Networks in Real-time Fraud Detection with Low Latency* details an end-to-end GNN architecture designed specifically to address latency and future-information leakage in real-time fraud detection.
