# 19. Web security

## 1. Overview

To combat highly distributed, AI-powered botnets, securing modern web API login endpoints requires moving beyond static signatures. Attackers are no longer relying on noisy, high-volume attacks that trigger immediate alarms, but are instead using “low and slow” credential stuffing campaigns. These automated agents are constantly rotating through thousands of unique IP addresses, making infrequent authentication attempts – like one per minute – that bypass traditional rate-limiting firewalls. Defending against this threat requires a defense-in-depth API Gateway architecture that uses telemetry-driven machine learning. This approach uses device continuity signals, TLS fingerprinting, and application-layer behavioral analysis to distinguish legitimate users from stealthy botnets.

## 2. Thesis Statements

**Thesis Statement 1**
> Advancing web security at API login endpoints requires replacing static signature-based firewalls with adaptive, multi-layered machine learning analysis to identify and block AI-driven, low-frequency botnets.

**Thesis Statement 2**
> A comprehensive web security architecture that combines TLS fingerprinting and request-header analysis provides a highly accurate defensive mechanism, neutralizing low-and-slow credential stuffing attacks at the API Gateway.

## 3. Literature Review

**Literature Review supporting Thesis Statement 1**

Current literature emphasizes the necessity of transitioning from rigid, rule-based edge defenses to adaptive security frameworks.[^1]

*   **Title:** *Machine Learning for Securing API Gateways: A Systematic Literature Review*
*   **Authors:** B. Junedi Hutagaol, Riama Santy Sitorus, Dita Madonna Simanjuntak
*   **Methodology and Findings:** Recent systematic reviews demonstrate that embedding machine learning models directly into API gateways allows for real-time anomaly detection. These systems establish behavioral baselines capable of distinguishing between legitimate human traffic and distributed, low-rate credential stuffing that evades traditional volume-based rate limiting.
*   **Link:** https://www.researchgate.net/publication/395047921_Machine_Learning_for_Securing_API_Gateways_a_Systematic_Literature_Review
* [Link to Article](/19.3/1.1/Machine_Learning_for_Securing_API_Gateways_a_Syste.pdf)

**Literature Review supporting Thesis Statement 2**

Research into cryptographic fingerprinting validates its efficacy in identifying automated traffic regardless of IP address rotation.[^2]

*   **Title:** *When Handshakes Tell the Truth: Detecting Web Bad Bots via TLS Fingerprints*
*   **Authors:** Ghalia Jarad, Kemal Bicakci
*   **Methodology and Findings:** Studies utilizing JA4 and JA3 TLS fingerprinting techniques coupled with gradient-boosted classifiers (such as XGBoost) have proven highly accurate in detecting evasive bots. By analyzing the low-level TLS handshake parameters, administrators can reliably correlate distributed attacks back to their originating botnet families, forming a robust defensive layer at the API gateway.
*   **Link:** https://arxiv.org/abs/2602.09606
* [Link to Article](/19.3/2.1/2602.09606v1.pdf)

**Literature Review supporting Thesis Statement 1 & 2**

The integration of explainable AI (XAI) within cloud-native architectures further reinforces adaptive API defense mechanisms.[^3]

*   **Title:** *AI-Driven Real-Time API Security: Explainable Threat Detection for Cloud Environments*
*   **Authors:** Akshay Mittal, Pragya Keshap, Arpana Hosabettu
*   **Methodology and Findings:** Emerging research highlights how combining anomaly detection (e.g., Isolation Forests) with interpretability tools (e.g., SHAP) allows DevOps teams to deploy transparent, low-latency threat mitigation that accurately flags anomalous header and behavioral patterns while minimizing false positives.
*   **Link:** https://www.techrxiv.org/doi/full/10.36227/techrxiv.175695570.09221013/v1
* [Link to Article](/19.3/3.1/techrxiv.175695570.09221013_v1.pdf)
