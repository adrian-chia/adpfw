# 15. Self-learning systems

## 1. Overview

Machine learning models in cybersecurity continuously update their baseline behaviors to identify low-and-slow credential stuffing. Attackers now use distributed, AI-powered botnets that rotate through thousands of IP addresses, sometimes making just one login attempt per minute per IP. Conventional API Gateways use static rules, such as banning an IP address only after it crosses a set request threshold, so they miss these slow attacks. 

Adaptive learning systems evaluate real-time telemetry instead. They analyze HTTP request headers, IP reputation, device characteristics, authentication failure rates, and TLS fingerprints like JA3 or JA4. By aggregating this data at the campaign level, the system learns what normal human traffic looks like. Administrators can then use a dynamic throttling algorithm at the API Gateway to stop distributed botnets before they steal credentials.

## 2. Thesis Statements

**Thesis Statement 1**
> A self-learning system in a cloud-native API Gateway can block low-and-slow credential stuffing by continuously evaluating device and TLS fingerprints, catching campaigns that bypass static rules.

**Thesis Statement 2**
> An adaptive API throttling mechanism powered by reinforcement learning continuously updates its baseline to adjust access restrictions. It prevents botnets from testing compromised credentials while letting legitimate users log in.

## 3. Literature Review

**Literature Review supporting Thesis Statement 1**

Recent fingerprinting studies show that analyzing TLS handshakes helps detect low-and-slow threats.[^1] 

*   **Title:** *When Handshakes Tell the Truth: Detecting Web Bad Bots via TLS Fingerprints*
*   **Authors:** Ghalia Jarad, Kemal Bicakci
*   **Methodology and Findings:** The authors tested whether protocol-level JA4 TLS fingerprinting could separate bots from human users. They trained machine learning classifiers, including CatBoost and XGBoost, on the JA4DB dataset. Bot tools use different underlying libraries than web browsers, so their TLS `ClientHello` patterns differ. The study found this method detects bots with high accuracy (AUC 0.998). Analyzing TLS fingerprints identifies credential stuffing scripts even when attackers spoof `User-Agent` strings or rotate IP addresses.
*   **Link:** https://arxiv.org/abs/2602.09606
* [Link to Article](/15.3/1.1/2602.09606v1.pdf)

**Literature Review supporting Thesis Statement 2**

Research into reinforcement learning (RL) shows that self-learning systems can adjust API rate limits dynamically.[^2][^3]

*   **Title:** *Multi-Objective Adaptive Rate Limiting in Microservices Using Deep Reinforcement Learning*
*   **Authors:** Ning Lyu, Yuxi Wang, Ziyu Cheng, Qingyuan Zhang, Feng Chen
*   **Methodology and Findings:** The researchers built a deep RL framework using A3C and DQN algorithms to adjust rate limits based on traffic and system load. They replaced static thresholds with a dynamic model that learns from environmental feedback. The new model lowered latency and improved throughput. The study shows that adaptive limits can block abuse without disrupting the system or blocking regular users.
*   **Link:** https://arxiv.org/abs/2511.03279
* [Link to Article](/15.3/2.1/2511.03279v1.pdf)

*   **Title:** *Designing CAPTCHA Systems with Reinforcement Learning for Adaptive Defense*
*   **Authors:** Meghana Indukuri, Eman Naseerkhan, Joshua Rose, Martin Tran, Younghee Park
*   **Methodology and Findings:** The authors modeled bot detection as a Partially Observable Markov Decision Process (POMDP) and used a PPO+LSTM agent to adjust security responses. Instead of using volume-based triggers, the system shows CAPTCHAs dynamically based on the classification model's real-time confidence scores. The results showed that this strategy stops advanced bot attacks, such as credential stuffing. It adds friction only when the risk of malicious intent is high, letting regular users proceed without interruption.
*   **Link:** https://www.mdpi.com/2079-9292/15/11/2363
* [Link to Article](/15.3/2.2/electronics-15-02363.pdf)
